# Draft message

The draft is for the recipient, not for the user. The user already has the investigation. The recipient needs only what lets them act.

## Rules

- **Length.** Without a stated length, keep it to 3 to 5 sentences or bullets. When the user says "short" or "very short", keep it to 2 to 3 lines. A handover doc fits on one screen.
- **Content.** Give the outcome, the one cause that matters, and the one action the recipient must take. Leave out file paths, line numbers, function names, and log IDs unless the recipient is a developer who will open that code.
- **The user's own draft.** Keep the user's wording and length. Fix only what is wrong or unclear. Don't add new points. Name any point you think is missing in one line after the draft, and let the user decide.
- **Revisions.** Return only the new draft. Don't explain what changed unless the user asks.
- **Tone.** Plain and friendly, written as the user in the first person.
- **Posting.** Don't post or send it. Offer to post it in one line.
